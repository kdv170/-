# Обработка «Перенос исполнительных листов ЗУП → ERP»

## 1. Назначение

Перенос документов **ИсполнительныйЛист** из **1С:Зарплата и управление персоналом 3.1** в **1С:ERP Управление предприятием 2.x**.

Отбираются только документы, **действующие на дату переноса**. Источник истины — периодический регистр сведений **ПлановыеУдержания**: берётся `СрезПоследних` на дату переноса, условие `Действует = Истина` и основание типа `Документ.ИсполнительныйЛист`.

Такой отбор корректнее, чем просто «все документы за период», потому что:

- прекращённые/приостановленные удержания (документы прекращения, окончание срока) в перенос не попадают;
- учитываются изменения размера удержания и получателя, проведённые отдельными документами;
- повторный перенос на ту же дату идемпотентен (дубли не создаются — см. п. 5).

## 2. Режимы работы

Одна и та же внешняя обработка открывается и в ЗУП, и в ERP. Текущая конфигурация определяется автоматически (`Метаданные.Имя` + проверка подсистемы зарплаты).

| Режим | Где выполняется | Как работает |
|---|---|---|
| Заполнение по регистру + выгрузка в файл | ЗУП | Запрос к `ПлановыеУдержания.СрезПоследних`, сериализация найденных документов в JSON |
| Загрузка из файла | ERP | Чтение JSON, сопоставление НСИ, создание документов `ИсполнительныйЛист` с сохранением ГУИДа из ЗУП |
| Прямой перенос через COM | ERP (приёмник), ЗУП — источник | Подключение `V83.COMConnector` к базе ЗУП, чтение действующих листов «на лету», создание в ERP без промежуточного файла |

## 3. Установка

### 3.1. Создание .epf из исходников

1. Конфигуратор → `Файл → Новый → Внешняя обработка`.
2. В модуль объекта вставить целиком `ObjectModule.bsl`.
3. Создать основную форму по описанию из `FormDescription.md` (реквизиты, таблицы, команды).
4. В модуль формы вставить `ManagedFormModule.bsl`.
5. Сохранить как `ПереносИсполнительныхЛистовЗУПвERP.epf`.

### 3.2. Подключение через БСП

Подсистема `ДополнительныеОтчетыИОбработки` подхватит обработку автоматически — функция `СведенияОВнешнейОбработке()` уже есть в модуле объекта (вид — `ДополнительнаяОбработка`, назначение — обе конфигурации, безопасный режим — `Ложь`, т.к. используются COM и работа с файлами).

### 3.3. Права

- Выгрузка (ЗУП): чтение документов `ИсполнительныйЛист`, регистра `ПлановыеУдержания`, справочников `Сотрудники`, `ФизическиеЛица`, `Контрагенты`, `Организации`.
- Загрузка (ERP): добавление/изменение документов `ИсполнительныйЛист`, чтение/создание элементов НСИ для сопоставления, проведение.
- Для COM-режима на клиенте ERP должен быть зарегистрирован `V83.COMConnector` той же разрядности, что и клиент 1С.

## 4. Порядок работы (через файл)

**Шаг 1 — ЗУП:**
1. Открыть обработку, указать **Дату переноса** (смысл — «действующие на конец этого дня»).
2. Опционально указать **Организацию** (пусто = по всем организациям).
3. Нажать **«Заполнить по регистру»**. Таблица заполнится строками: документ, сотрудник, физлицо, получатель, период, размер удержания, вид удержания.
4. Флажком **«Переносить»** отметить нужные строки (по умолчанию отмечены все).
5. Нажать **«Выгрузить в файл»**, выбрать путь `*.json`. Рядом с файлом можно сохранить протокол.

**Шаг 2 — ERP:**
1. Открыть обработку, указать файл обмена.
2. Установить флажки **«Обновлять существующие»** (перезаписывать реквизиты найденных по ГУИДу документов) и **«Проводить документы»** (иначе документы запишутся черновиком).
3. Нажать **«Загрузить из файла»**.
4. Разобрать **Протокол**: зелёные строки — созданы/обновлены, жёлтые — пропущены (дубль без флага обновления), красные — ошибки сопоставления.

**Шаг 3 — контроль:**
- Сверьте количество: строк с флажком в ЗУП = созданных + обновлённых в ERP.
- Откройте 2–3 документа в ERP, проверьте сотрудника, получателя, период, размер, conducting.
- Постройте в ERP отчёт по регистру `ПлановыеУдержания` на дату переноса — состав должен совпасть с выгруженным.

## 5. Сопоставление НСИ и защита от дублей

При загрузке каждый объект ищется сначала **по ГУИДу** (`УникальныйИдентификатор`), затем по запасному ключу:

- Организация → ГУИД, иначе ИНН+КПП;
- Физическое лицо → ГУИД, иначе ФИО+дата рождения (+ИНН при наличии);
- Сотрудник → ГУИД, иначе физлицо+организация (действующий трудовой договор; если договоров несколько — берётся первый действующий, в протокол пишется предупреждение);
- Получатель-контрагент → ГУИД, иначе ИНН (+КПП); получатель-физлицо — как физлицо;
- Вид удержания (ПВР `Удержания`) → код, иначе наименование; если не найден — подставляется удержание по умолчанию и пишется предупреждение.

Документ в ERP создаётся с **той же ссылкой**, что в ЗУП (`УстановитьСсылкуНового(Новый УникальныйИдентификатор(ГУИД))`). Поэтому повторная загрузка того же файла:

- без флага «Обновлять» — пропускается как дубль;
- с флагом — обновляет реквизиты, не плодя копии.

Документы с пометкой удаления в ЗУП в выгрузку **не попадают** (условие в запросе). Если лист удалён в ЗУП уже после переноса — в ERP он не снимается автоматически, это делается вручную (защита от потери данных).

## 6. Формат файла обмена

JSON, кодировка UTF-8. Корень — объект:

```json
{
  "ВерсияФормата": "1.0",
  "Источник": "ЗУП",
  "ДатаВыгрузки": "2026-10-18T10:00:00",
  "ДатаПереноса": "2026-10-18",
  "Документы": [ { ...один исполнительный лист... }, ... ]
}
```

Состав элемента `Документы` — см. `ExchangeExample.json`. Все ссылки дублируются парой `ГУИД + человекочитаемые поля` (ИНН, ФИО и т.д.), чтобы загрузка работала даже при рассинхроне ГУИдов между базами.

## 7. Прямой перенос через COM

На форме ERP заполнить: вариант подключения (`Srvr="..." / File="..."`), имя базы, пользователя, пароль. Нажать **«Прямой перенос»**. Под капотом:

1. `V83.COMConnector.Connect(СтрокаПодключения)` → соединение с ЗУП;
2. в соединении выполняется тот же отбор по `ПлановыеУдержания.СрезПоследних` (через `Соединение.NewObject("Запрос")`);
3. результат построчно сериализуется в структуры и создаётся в текущей базе ERP той же процедурой, что и загрузка из файла.

При обрыве соединения перенос прерывается, уже созданные документы остаются (транзакция — на каждый документ отдельно), в протоколе видно, на какой строке произошёл обрыв. Повторный запуск доберёт остаток без дублей.

## 8. Разбор частых ошибок

| Сообщение в протоколе | Причина | Что делать |
|---|---|---|
| `Организация не найдена (ИНН ...)` | В ERP нет организации с таким ИНН | Создать организацию в ERP / исправить ИНН в ЗУП |
| `Сотрудник не найден, физлицо ...` | Нет сотрудника/физлица в ERP | Перенести кадровый состав (штатный обмен ЗУП↔ERP) и повторить |
| `Вид удержания "X" не найден, подставлено удержание по умолчанию` | Рассинхрон ПВР Удержания | Синхронизировать виды удержаний, перепровести документы |
| `Документ уже существует, пропущен` | Повторная загрузка без флага обновления | Норма; для перезаписи включить «Обновлять существующие» |
| `Ошибка проведения: ...` | Не заполнены обязательные реквизиты ERP (напр. подразделение, статья) | Открыть документ, дозаполнить, провести вручную |
| `COM: ошибка подключения (0x...)` | Неверная строка подключения / нет прав / разрядность COMConnector | Проверить строку, пользователя, одинаковость x86/x64 |
| Пустая таблица после заполнения | На дату переноса нет действующих удержаний либо все с пометкой удаления | Сменить дату / проверить регистр отчётом «Плановые удержания» |

## 9. Адаптация под свой релиз

Имена реквизитов документа `ИсполнительныйЛист` и измерений регистра `ПлановыеУдержания` менялись между релизами. В коде все обращения к «плавающим» реквизитам обёрнуты проверками `Метаданные...Найти(...) <> Неопределено` с запасными вариантами. Если в вашей конфигурации поле называется иначе (например `ДатаНачала` vs `ДатаС`), добавьте соответствие в функции `ПрочитатьРеквизитыИсполнительногоЛиста()` (модуль объекта, область «Выгрузка») — помечено комментарием `// АДАПТАЦИЯ:`.

## 10. Проверка перед промышленной эксплуатацией

1. Скопировать ERP в тестовую базу.
2. Выгрузить из ЗУП 3–5 листов, загрузить в тестовую ERP.
3. Сверить построчно: сотрудник, получатель, период, размер/процент, проведение.
4. Проверить расчёт зарплаты за месяц переноса на тестовой копии.
5. Только после этого переносить в рабочую ERP.
