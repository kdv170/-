# Загрузка учета доходов НДФЛ из ЗУП (COM)

Внешняя обработка для 1С:ERP. Читает обороты регистра накопления «Учет доходов для исчисления НДФЛ» (`СведенияОДоходахНДФЛ`) из 1С:ЗУП через COM и записывает их в ERP документами «Перенос данных».

Исходники лежат в `src/` в формате выгрузки внешней обработки (версия формата 2.17). Готового EPF в репозитории нет: на среде сборки нет платформы 1С.

## Что переносится

Берутся активные записи основной таблицы регистра за выбранный период, а не весь регистр и не виртуальная таблица `Обороты`. У регистра вида «Обороты» каждая запись и есть оборот. Так сохраняются измерения, ресурсы и реквизиты, в том числе исходный период движения.

Регистратор из ЗУП не переносится. Набор записей пишется с отбором по новому документу `ПереносДанных`, поэтому регистратором каждой записи становится этот документ.

Период режется по календарным месяцам. На каждый месяц, в котором есть что записать, создается отдельный документ. Дата документа — конец этого месяца, период каждой записи остается исходным. Пустой месяц документ не создает.

Если в отборе указана организация, срез месяца строится по ее ИНН и КПП и не затирает обороты других организаций. Без организации один документ месяца содержит все организации.

Повторный запуск с включенным «Замещать ранее загруженное» перезаписывает документ того же месяца. Документ ищется по комментарию:

`ЗагрузкаНДФЛИзЗУП|<регистр>|<ИНН/КПП или ВСЕ>|<yyyyMM>|Не перепроводить: регистратор заменен на этот документ`

## Как запустить

Обработка рассчитана на ERP с зарплатным контуром (есть регистр `СведенияОДоходахНДФЛ` и документ `ПереносДанных`) и на ЗУП 3.1 с тем же именем регистра. COM работает в толстом или тонком клиенте Windows. Веб-клиент и Linux-клиент соединение не откроют.

1. На Windows зарегистрируйте коннектор платформы той же версии, что и клиент: `regsvr32 comcntr.dll` из каталога `bin` платформы.
2. Соберите EPF одним из способов ниже.
3. Откройте обработку в ERP или зарегистрируйте ее в «Дополнительных отчетах и обработках». Безопасный режим должен быть выключен, иначе COM недоступен. В сведениях БСП безопасный режим уже задан как `Ложь`.
4. Укажите серверную или файловую базу ЗУП, пользователя с правом чтения регистра и период.
5. Нажмите «Проверить подключение»: в журнале будет число активных записей за весь выбранный период.
6. Нажмите «Загрузить». Месяцы читаются по очереди, порциями по 400 строк.

Нужны права на запись документа `ПереносДанных` и регистра, а для пересчета итогов — право управления итогами регистра.

## Сборка EPF

Командой конфигуратора из каталога `src`:

```bat
1cv8.exe DESIGNER /F "C:\BaseERP" /LoadExternalDataProcessorOrReportFromFiles "C:\src\ЗагрузкаУчетаДоходовНДФЛИзЗУП.xml" "C:\ЗагрузкаУчетаДоходовНДФЛИзЗУП.epf"
```

Вручную: новая внешняя обработка с именем `ЗагрузкаУчетаДоходовНДФЛИзЗУП`, в модуль объекта вставить `src/ЗагрузкаУчетаДоходовНДФЛИзЗУП/Ext/ObjectModule.bsl`, добавить управляемую форму `Форма` и вставить модуль `src/ЗагрузкаУчетаДоходовНДФЛИзЗУП/Forms/Форма/Ext/Form/Module.bsl`. События формы `ПриСозданииНаСервере`, `ПриОткрытии` и `ПриЗакрытии` уже указаны в выгрузке формы.

## Поведение загрузки

- Состав полей берется из метаданных ЗУП и ERP. Переносятся только поля с совместимым типом. Если обязательное поле перенести нельзя, загрузка останавливается до записи.
- Ссылки через COM не передаются. Организации ищутся по ИНН и КПП, физические лица — по СНИЛС, затем ИНН, затем ФИО и дате рождения, сотрудники — по физическому лицу и коду или наименованию, прочие справочники — по коду. Неоднозначное совпадение не выбирается.
- Необязательная ссылка, которой нет в ERP, остается пустой. Обязательная несопоставленная ссылка пропускает всю строку. `ДокументОснование` заполняется, только если такой документ уже есть в ERP. Регистратором он не становится.
- Запись идет в режиме загрузки: документ не проводится обычным проведением. Пустое проведение стерло бы движения. В комментарии прямо указано, что документ перепроводить нельзя.
- Флаг «Пропускать, если в ERP уже есть движения» по умолчанию включен. Месяц пропускается, если за его интервал уже есть активные записи другого регистратора. Записи предыдущей загрузки с тем же маркером своими не считаются, поэтому загрузку одной организации можно дополнить другой.
- В журнале месяца сравниваются число строк и сумма `СуммаДохода` в ЗУП и в записанном наборе.
- После записи хотя бы одного документа итоги регистра пересчитываются один раз. Пока итоги не пересчитаны, отчеты по оборотам могут не увидеть новые записи. Если пересчет не удался, документы уже записаны: пересчитайте итоги регистра вручную.

Имя регистра по умолчанию `СведенияОДоходахНДФЛ`. Если в базе другое имя, укажите точное имя или синоним «Учет доходов для исчисления НДФЛ» либо «Учет данных для НДФЛ». Имя в ЗУП и ERP должно совпасть.
