# Загрузка регистра «Учет данных для НДФЛ» из 1С:ЗУП в 1С:ERP через COM

Внешняя обработка для конфигурации **1С:ERP** (управляемая форма, платформа 8.3). Она подключается к базе **1С:ЗУП** через COM-соединение (`V83.COMConnector`), читает записи регистра «Учет данных для НДФЛ» и записывает их в одноименный регистр ERP.

Исходники лежат в формате выгрузки конфигуратора («Выгрузить в файлы»):

```
src/
├── ЗагрузкаУчетаДанныхДляНДФЛИзЗУП.xml                      # описание внешней обработки
└── ЗагрузкаУчетаДанныхДляНДФЛИзЗУП/
    └── Forms/
        ├── Форма.xml                                         # описание формы
        └── Форма/Ext/
            ├── Form.xml                                      # элементы, реквизиты и команды формы
            └── Form/Module.bsl                               # вся логика загрузки
```

## Сборка в `.epf`

Через конфигуратор: **Файл → Открыть…** → выбрать `src/ЗагрузкаУчетаДанныхДляНДФЛИзЗУП.xml` → **Файл → Сохранить как…**.

Из командной строки (любая пустая или служебная база):

```bat
1cv8.exe DESIGNER /F "C:\Bases\Empty" /LoadExternalDataProcessorOrReportFromFiles ^
  "src\ЗагрузкаУчетаДанныхДляНДФЛИзЗУП.xml" "ЗагрузкаУчетаДанныхДляНДФЛИзЗУП.epf"
```

Версия формата XML указана в атрибуте `version` (сейчас `2.9`, платформа 8.3.16 и новее). Если ваша платформа старше или выдает ошибку формата, замените номер версии в трех XML-файлах на тот, что получается при выгрузке из вашей платформы.

## Как пользоваться

1. Откройте `.epf` в ERP через **Файл → Открыть** (в тонком или толстом клиенте). Из «Дополнительных отчетов и обработок» обработка не заработает: там безопасный режим запрещает создание COM-объектов.
2. Заполните подключение к ЗУП: файловая база (каталог) или серверная (сервер и имя базы), пользователь и пароль. Пароль не сохраняется, остальные параметры запоминаются в настройках пользователя.
3. Нажмите **Проверить подключение и найти регистры**. Обработка ищет регистр сведений или накопления по синониму «Учет данных для НДФЛ» (либо по имени) в ЗУП и в ERP и выводит в журнал их измерения, ресурсы и реквизиты. Если регистр называется иначе, укажите его имя в полях «Регистр-источник» и «Регистр-приемник» (имя или полное имя, например `РегистрСведений.ИмяРегистра`).
4. При необходимости задайте период и условие запроса. Условие пишется на языке запросов с псевдонимом `Т`, например `Т.Организация.ИНН = "7701234567"`.
5. Запустите **Загрузить** сначала с флажком **Только проверка** (по умолчанию включен). В этом режиме ничего не записывается: журнал покажет, сколько записей прочитано, какие ссылки не сопоставились и что будет создано.
6. Снимите флажок и повторите загрузку.

## Как работает загрузка

- Данные читаются запросом `ВЫБРАТЬ * ИЗ <регистр>`. Набор полей берется из результата запроса, поэтому обработка не зависит от версии ЗУП. Загружаются только поля, которые есть и в источнике, и в приемнике.
- Ссылки (физические лица, организации, подразделения, перечисления и т. д.) сопоставляются так:
  1. по уникальному идентификатору, если такой объект уже есть в ERP (например, после обмена);
  2. по реквизитам:
     - физические лица: СНИЛС, затем ИНН, затем наименование и дата рождения;
     - организации: ИНН и КПП, затем ИНН, затем наименование;
     - документы: номер и дата;
     - остальные справочники: код и наименование, затем наименование;
     - предопределенные элементы сопоставляются по имени предопределенных данных;
  3. если флажок **Создавать отсутствующие элементы** включен, отсутствующий элемент справочника создается с тем же идентификатором и найденными реквизитами. Это грубое создание без заполнения связанных данных, поэтому для физических лиц лучше сначала выполнить обмен справочниками.
- Значения перечислений переносятся по имени значения.
- Результат сопоставления кэшируется, поэтому каждая ссылка ищется один раз. Несопоставленные ссылки записываются в журнал один раз.
- Записи с несопоставленными ссылками по умолчанию пропускаются (флажок **Пропускать записи с несопоставленными ссылками**). Это защищает от записи данных с пустыми ссылками.
- Независимый регистр сведений записывается построчно: набор записей отбирается по всем измерениям (и по периоду, если регистр периодический) и записывается с заменой. Если какого-то измерения приемника нет в источнике, загрузка отменяется, чтобы не перезаписать лишние данные.
- Регистр, подчиненный регистратору (в том числе регистр накопления), записывается по регистраторам. Регистратор сопоставляется как документ (идентификатор, затем номер и дата). Движения найденного в ERP документа заменяются целиком. Используйте этот режим осторожно.
- Регистры бухгалтерии и расчета не поддерживаются.

## Ограничения и требования

- COM-коннектор работает на стороне сервера 1С:ERP (код выполняется на сервере), поэтому на машине, где выполняется серверный код, должен быть зарегистрирован `comcntr.dll` (Windows). На Linux-сервере COM недоступен, нужен другой способ обмена.
- Версия платформы ЗУП и ERP должна позволять подключение через COM (платформы 8.3, разрядность коннектора должна соответствовать разрядности процесса, в котором он запускается).
- Пользователю, под которым выполняется подключение к ЗУП, нужны права на чтение регистра и справочников, а в ERP — на запись регистра.
- Обработка написана без доступа к платформе 1С, поэтому **не запускалась в реальной конфигурации**. Проверена только корректность XML и парность конструкций в модуле. Перед рабочим использованием прогоните загрузку в режиме проверки на копии базы.
