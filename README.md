# Перенос исполнительных листов из 1С:ЗУП в 1С:ERP

Внешняя обработка `ПереносИсполнительныхЛистов` (исходники в формате выгрузки конфигуратора) переносит документы
`ИсполнительныйЛист` из 1С:Зарплата и управление персоналом 3.1 в 1С:ERP.

Отбор документов выполняется по регистру сведений `ПлановыеУдержания`: переносятся только исполнительные листы,
по которым на дату переноса есть действующие удержания.

## Сборка обработки

Из каталога репозитория (платформа 8.3.20+):

```
1cv8.exe DESIGNER /F <путь к любой файловой базе> /LoadExternalDataProcessorOrReportFromFiles ^
    ПереносИсполнительныхЛистов.xml ПереносИсполнительныхЛистов.epf
```

Либо в конфигураторе: *Файл - Открыть*, выбрать `ПереносИсполнительныхЛистов.xml`, затем *Файл - Сохранить как*.

## Порядок работы

1. **ЗУП, вкладка «Выгрузка из ЗУП».** Указать дату переноса, нажать «Подобрать документы» - в список попадут документы
   `ИсполнительныйЛист`, на которые ссылаются записи среза последних `ПлановыеУдержания` на конец указанного дня.
   Записи с действием «Прекратить» и документы, помеченные на удаление, не учитываются. Снять лишние пометки,
   нажать «Выгрузить в файл» - сохраняется XML-файл.
2. **ERP, вкладка «Загрузка в ERP».** «Открыть файл», отметить документы, при необходимости включить «Только проверка»,
   затем «Загрузить в ERP». Результат по каждому документу виден в списке, подробности - в протоколе.

Организации, физические лица и сотрудники должны быть уже перенесены в ERP (обычным переносом кадровых данных):
обработка ищет их в ERP, а не создает.

## Как определяются действующие удержания

Запрос строится по метаданным регистра: поле со ссылкой на `ИсполнительныйЛист` ищется среди измерений, ресурсов и
реквизитов `ПлановыеУдержания` (если такого поля нет, а регистр подчинен регистратору, используется регистратор).
Если у регистра есть поле `Действие`, значения «Прекратить» исключаются.

## Сопоставление ссылок в ERP

Каждая ссылка в файле хранится вместе с ключевыми реквизитами (код, наименование, ИНН, КПП, СНИЛС, дата рождения,
владелец, номер счета, физическое лицо и головная организация сотрудника). При загрузке для объекта пробуются
по очереди:

1. предопределенный элемент с тем же именем;
2. СНИЛС; ИНН + КПП; ИНН;
3. физическое лицо + головная организация (сотрудники);
4. владелец + номер счета; владелец + наименование;
5. наименование + дата рождения; код + наименование; наименование (без даты рождения).

Для документов-ссылок используются номер, дата и организация, для перечислений - имя значения.
Если найдено несколько подходящих элементов, ссылка считается несопоставленной (можно включить «брать первый»).
По умолчанию документы с несопоставленными ссылками пропускаются и попадают в протокол.

## Особенности загрузки

- Реквизиты и табличные части копируются по именам; отсутствующие в ERP поля пропускаются с предупреждением в протоколе.
- Существующий документ ERP ищется по номеру, дате и организации; по умолчанию он пропускается
  (флажок «Обновлять документы, уже имеющиеся в ERP» перезаполняет его).
- Документы, проведенные в ЗУП, проводятся в ERP; при ошибке проведения документ остается записанным без проведения.

## Проверка

Исходники не проверялись на живых конфигурациях ЗУП и ERP: перед рабочим переносом выполните загрузку с флажком
«Только проверка» и сверьте протокол. Структура `ИсполнительныйЛист` в ЗУП и ERP может отличаться по версиям -
расхождения попадут в протокол как предупреждения.
