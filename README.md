# Перенос исполнительных листов из ЗУП в ERP

Внешняя обработка `ПереносИсполнительныхЛистов` переносит документы **«Исполнительный лист»** из
«1С:Зарплата и управление персоналом 3.1» в «1С:ERP Управление предприятием 2».

В перенос попадают только листы, удержание по которым **действует на дату переноса** по регистру сведений
**«Плановые удержания»** (`РегистрСведений.ПлановыеУдержания`).

## Состав

```
src/
  ПереносИсполнительныхЛистов.xml              корневой файл обработки (формат выгрузки Конфигуратора 8.3)
  ПереносИсполнительныхЛистов/
    Ext/ObjectModule.bsl                       отбор, выгрузка, сопоставление и загрузка
    Forms/Форма.xml
    Forms/Форма/Ext/Form.xml                   управляемая форма
    Forms/Форма/Ext/Form/Module.bsl
```

## Сборка `.epf`

Конфигуратор: откройте или создайте любую внешнюю обработку, загрузите в нее файлы командой загрузки из файлов
(меню «Действия»), укажите `src/ПереносИсполнительныхЛистов.xml` и сохраните как `ПереносИсполнительныхЛистов.epf`.
В 1C:EDT можно импортировать каталог `src` как внешнюю обработку в формате XML Конфигуратора.

Пакетный режим:

```
"C:\Program Files\1cv8\8.3.xx.xxxx\bin\1cv8.exe" DESIGNER /F"C:\Temp\ПустаяБаза" ^
  /LoadExternalDataProcessorOrReportFromFiles "src\ПереносИсполнительныхЛистов.xml" "ПереносИсполнительныхЛистов.epf"
```

Нужна платформа 8.3.16 или новее. Одна и та же обработка открывается в обеих базах через «Файл» → «Открыть».

## Порядок работы

### 1. Выгрузка в ЗУП (вкладка «Выгрузка из ЗУП»)

1. Укажите дату в поле **«Действующие на дату»** и, если нужно, организацию.
2. Нажмите **«Заполнить»**. Список строится так:
   - берется срез последних регистра «Плановые удержания» на конец указанного дня;
   - остаются записи, у которых поле-основание (`ДокументОснование`) ссылается на документ «Исполнительный лист»,
     а ресурс `Действует = Истина`. Условие накладывается на результат среза, поэтому удержания, прекращенные
     до даты переноса, в список не попадают;
   - выбираются только проведенные документы.
3. Отметьте нужные документы и нажмите **«Выгрузить в файл…»**. Получится JSON-файл
   `ИсполнительныеЛисты_ГГГГММДД.json`.

### 2. Загрузка в ERP (вкладка «Загрузка в ERP»)

1. Нажмите **«Открыть файл…»** и выберите выгруженный файл. Отметка «Есть в базе» стоит у документов,
   которые уже переносились: их ищут по уникальному идентификатору.
2. Настройки:
   - **Проводить документы**: проводить документы, которые проведены в ЗУП. Если провести не удалось, документ
     записывается без проведения, а причина попадает в колонку «Сообщение»;
   - **Сохранять номера документов**: перенести номер из ЗУП. Если флажок снят, новым документам номер
     присвоит ERP;
   - **Перезаписывать ранее перенесенные**: обновить документы, которые уже есть в базе. Если флажок снят,
     они пропускаются.
3. Нажмите **«Загрузить в базу»**. Результат по каждому документу выводится в колонках «Результат» и «Сообщение».
   Ссылки, которые не удалось сопоставить, собираются в таблице «Не найдены в информационной базе».

Ошибки также записываются в журнал регистрации с событием «Перенос исполнительных листов».

## Как переносятся данные

- Документ создается в ERP с **тем же уникальным идентификатором**, что и в ЗУП. Поэтому повторный перенос
  обновляет документ, а не создает дубль.
- Переносятся все реквизиты и табличные части, которые есть в документе и в ЗУП, и в ERP (сопоставление по
  имени). Если реквизит из ЗУП не нашелся в ERP, в протокол пишется замечание.
- Значения перечислений сопоставляются по имени значения.
- Ссылочные значения ищутся по порядку:
  1. по уникальному идентификатору (справочники, синхронизированные между ЗУП и ERP);
  2. по имени предопределенного элемента;
  3. по правилам поиска. Ссылка считается найденной только при **единственном** совпадении:

| Объект                                   | Правила (по порядку)                                                                  |
|------------------------------------------|---------------------------------------------------------------------------------------|
| Справочник.Организации, Контрагенты      | ИНН+КПП; ИНН; Наименование                                                            |
| Справочник.ФизическиеЛица                | ИНН; СНИЛС; Наименование+ДатаРождения; Наименование                                   |
| Справочник.Сотрудники                    | ФизЛицо+ГоловнаяОрганизация+Код; ФизЛицо+ГоловнаяОрганизация; ФизЛицо; Код+Наименование |
| Справочник.БанковскиеСчета…              | Владелец+НомерСчета; НомерСчета                                                       |
| Справочник.КлассификаторБанков           | Код (БИК); Наименование                                                               |
| Справочник.Пользователи                  | Наименование                                                                          |
| ПланВидовРасчета.Удержания               | Наименование+КатегорияУдержания; Наименование; КатегорияУдержания                     |
| Прочие справочники и планы видов расчета | Код+Наименование; Наименование                                                        |
| Документы                                | только по уникальному идентификатору                                                  |

  Правила задаются в процедуре `ИнициализироватьПравилаПоиска()` модуля объекта. Обработку для выгрузки и для
  загрузки нужно собирать из одной и той же версии исходников: по этим правилам определяется, какие поля
  выгружаются.
- Если ссылку найти не удалось, реквизит в ERP остается со значением по умолчанию, а запись попадает в таблицу
  «Не найдены в информационной базе». Заполните такие значения в ERP (или создайте недостающие элементы)
  и повторите загрузку с флажком «Перезаписывать ранее перенесенные».
