# Перенос документов «Исполнительный лист» из ЗУП в ERP

Внешняя обработка для переноса документов **ИсполнительныйЛист** из конфигурации **1С:ЗУП 3.1** в **1С:ERP 2.x**.

Принцип отбора: переносятся только те исполнительные листы, которые **действуют на дату переноса** по срезу регистра сведений **ПлановыеУдержания** (`СрезПоследних` на дату переноса, `Действует = Истина`, основание — `Документ ИсполнительныйЛист`).

## Состав репозитория

| Файл | Назначение |
|---|---|
| `PerenosIspolnitelnyhListovZUPvERP/ObjectModule.bsl` | Модуль объекта обработки. Вся серверная логика: отбор по регистру `ПлановыеУдержания`, выгрузка в JSON-файл, загрузка файла в ERP, прямой перенос через COM. Функция `СведенияОВнешнейОбработке()` для подключения через БСП. |
| `PerenosIspolnitelnyhListovZUPvERP/ManagedFormModule.bsl` | Модуль управляемой формы. Обработчики команд: «Заполнить по регистру», «Выгрузить в файл», «Загрузить из файла», «Прямой перенос через COM». |
| `PerenosIspolnitelnyhListovZUPvERP/FormDescription.md` | Описание формы: какие реквизиты, таблицы и команды создать в конфигураторе. |
| `PerenosIspolnitelnyhListovZUPvERP/ExchangeExample.json` | Пример файла обмена. |
| `PerenosIspolnitelnyhListovZUPvERP/README.md` | Подробная инструкция: установка, порядок переноса, сопоставление справочников, разбор ошибок. |

## Быстрый старт

### Вариант А — через файл (рекомендуется)

1. Откройте обработку в **ЗУП**: `Файл → Открыть → ПереносИсполнительныхЛистовЗУПвERP.epf`.
2. Укажите **Дату переноса** (обычно `ТекущаяДата()`), при необходимости — **Организацию**.
3. Нажмите **«Заполнить по регистру»** — таблица заполнится действующими на дату переноса исполнительными листами.
4. Снимите флажки с документов, которые переносить не нужно, нажмите **«Выгрузить в файл»**.
5. Откройте ту же обработку в **ERP**, укажите тот же файл, нажмите **«Загрузить из файла»**.
6. Проверьте **Протокол переноса** внизу формы.

### Вариант Б — прямое подключение (COM)

1. На форме укажите параметры базы ЗУП: кластер/путь, имя базы, пользователя, пароль.
2. Нажмите **«Прямой перенос»** — обработка сама подключится к ЗУП через `V83.COMConnector`, отберёт действующие листы на дату переноса и создаст их в текущей базе ERP.

Детали — см. `PerenosIspolnitelnyhListovZUPvERP/README.md`.

## Как собрать .epf

1. В конфигураторе (`ЗУП` или `ERP`): `Файл → Новый → Внешняя обработка`.
2. Скопируйте `ObjectModule.bsl` в модуль объекта, создайте форму по `FormDescription.md`, скопируйте `ManagedFormModule.bsl` в модуль формы.
3. Сохраните как `ПереносИсполнительныхЛистовЗУПвERP.epf`.
4. Для подключения через «Дополнительные отчеты и обработки» функция `СведенияОВнешнейОбработке()` уже включена.

## Ключевой запрос отбора

```bsl
// Срез регистра ПлановыеУдержания на дату переноса:
// только действующие удержания с основанием ИсполнительныйЛист
ВЫБРАТЬ ...
ИЗ РегистрСведений.ПлановыеУдержания.СрезПоследних(
        &ДатаПереноса,
        Документ ССЫЛКА Документ.ИсполнительныйЛист
        И Действует = ИСТИНА) КАК Срез
```

Полный текст запроса — в функции `ДействующиеИсполнительныеЛисты()` модуля объекта.

## Сопоставление при загрузке в ERP

- **Организация** — по ГУИДу, запасной вариант по ИНН+КПП.
- **Физическое лицо** — по ГУИДу, запасной вариант по ФИО+дата рождения (+ИНН).
- **Сотрудник** — по ГУИДу, запасной вариант по физлицу + организации.
- **Получатель** (контрагент/физлицо) — по ГУИДу, запасной вариант по ИНН.
- **Документ** — по ГУИДу из ЗУП (`УстановитьСсылкуНового`), дубли не создаются; при установленном флажке «Обновлять существующие» реквизиты перезаписываются.
- **Вид удержания** (план видов расчета `Удержания`) — по коду/наименованию, иначе — удержание по умолчанию из настроек.

Несопоставленные позиции попадают в протокол и не блокируют перенос остальных.
