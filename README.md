# Загрузка данных учета НДФЛ из 1С:ЗУП в 1С:ERP через COM-соединение

Внешняя обработка для **1С:ERP Управление предприятием 2** (управляемые формы, платформа 8.3.16+).
Она подключается к информационной базе **1С:Зарплата и управление персоналом 3** через COM-соединение,
читает записи регистров учета НДФЛ и записывает их в одноименные регистры ERP.

ERP и ЗУП 3 построены на одной библиотеке БЗК, поэтому регистры НДФЛ в них совпадают по составу
(`СведенияОДоходахНДФЛ`, `РасчетыНалогоплательщиковСБюджетомПоНДФЛ`, `НДФЛПредоставленныеВычеты`,
`НДФЛИсчисленныйПоСтавкам` и т.д.). Обработка не привязана к конкретному списку: она показывает все регистры
накопления и сведений ЗУП, в имени или синониме которых есть «НДФЛ» (фильтр можно снять), и переносит общие
для источника и приемника поля.

## Состав

```
src/
  ЗагрузкаДанныхНДФЛИзЗУП.xml                     корневой файл обработки (формат выгрузки Конфигуратора)
  ЗагрузкаДанныхНДФЛИзЗУП/Ext/ObjectModule.bsl    модуль объекта: подключение, чтение, сопоставление, запись
  ЗагрузкаДанныхНДФЛИзЗУП/Forms/Форма.xml
  ЗагрузкаДанныхНДФЛИзЗУП/Forms/Форма/Ext/Form.xml
  ЗагрузкаДанныхНДФЛИзЗУП/Forms/Форма/Ext/Form/Module.bsl
build.bat                                         сборка .epf из исходников
```

## Сборка .epf

Собирать нужно в Конфигураторе базы ERP (или ее копии): у формы есть реквизит типа
`СправочникСсылка.Организации`, которого нет в пустой конфигурации.

* Вручную: Конфигуратор → **Файл → Загрузить внешнюю обработку, отчет из файлов...** → выбрать
  `src/ЗагрузкаДанныхНДФЛИзЗУП.xml` → **Файл → Сохранить как...** `ЗагрузкаДанныхНДФЛИзЗУП.epf`.
* Пакетно:

  ```bat
  set V8_EXE=C:\Program Files\1cv8\8.3.24.1467\bin\1cv8.exe
  set IB_CONN=/F"D:\Bases\ERP"
  set IB_USER=Администратор
  set IB_PWD=
  build.bat
  ```

  Результат — `build\ЗагрузкаДанныхНДФЛИзЗУП.epf`.

## Требования

* COM-соединение создается **на стороне сервера** ERP (в файловом варианте — в процессе клиента).
  Поэтому на этом компьютере (Windows) должна быть зарегистрирована `comcntr.dll` той же версии платформы,
  что и база ЗУП: `regsvr32 "C:\Program Files\1cv8\<версия>\bin\comcntr.dll"`.
  Для клиент-серверной ERP учетная запись службы сервера 1С должна иметь доступ к базе ЗУП
  (к каталогу файловой базы или к кластеру).
* Пользователь ЗУП, под которым выполняется подключение, должен иметь право внешнего соединения
  и чтения регистров НДФЛ.
* Обработку открывать через **Файл → Открыть** под пользователем с полными правами.
  В безопасном режиме (подключение через «Дополнительные отчеты и обработки» без разрешений) создание
  COM-объектов запрещено.

## Порядок работы

1. **Подключение к ЗУП** — выбрать вариант базы (файловая / клиент-серверная), указать каталог или
   кластер и имя базы, пользователя и пароль. ProgID соединителя по умолчанию `V83.COMConnector`.
   Нажать «Подключиться и получить список регистров».
2. **Регистры и отбор** — отметить регистры (по умолчанию отмечаются все регистры НДФЛ, которые есть в ERP),
   задать период (отбор по полю `Период`) и при необходимости организацию. Отбор по организации выполняется
   по **ИНН** через поле `Организация` (или `ГоловнаяОрганизация`) регистра, поэтому не зависит от того,
   совпадают ли идентификаторы организаций в базах.
3. **Параметры загрузки**:
   * *Регистраторы движений*:
     * «Документы-регистраторы из ЗУП» — движения записываются под тем же документом, что и в ЗУП.
       Документ ищется в ERP по уникальному идентификатору (так он совпадает, если документы переносились
       обменом). Если документ не найден, его движения пропускаются, либо, при включенном флаге
       «Создавать ненайденные документы-регистраторы», в ERP создается непроведенный документ того же вида
       с тем же идентификатором, датой, номером и организацией (запись в режиме обмена данными, без проверок).
     * «Все записи — в движения одного документа ERP» — все записи переносятся в движения выбранного
       документа (например, заранее созданной операции учета НДФЛ). Документ должен быть регистратором
       загружаемого регистра.
   * *Если значение не найдено в ERP* — что делать с записью, в которой ссылка (физлицо, организация,
     подразделение, значение перечисления и т.п.) не найдена: не загружать, загрузить с пустым значением
     или загрузить «битую» ссылку с идентификатором из ЗУП.
   * *Искать элементы справочников по ИНН/КПП и наименованию* — если элемент не найден по идентификатору:
     для справочников с реквизитом ИНН поиск по ИНН (+КПП), иначе по наименованию (+дате рождения для
     физических лиц). Неоднозначный результат считается ненайденным.
   * *Заменять существующие записи* — для подчиненных регистратору регистров набор записей документа
     в ERP заменяется загружаемыми записями (иначе записи добавляются к существующим);
     для независимых регистров сведений существующая запись с тем же ключом перезаписывается
     (иначе запись пропускается с сообщением в протоколе).
4. Нажать **«Загрузить данные»**. Ход и итоги (прочитано / записано / пропущено по каждому регистру,
   ненайденные объекты, поля, отсутствующие в одной из конфигураций) выводятся на закладку «Протокол».
   Однотипные сообщения ограничены 20 строками.

## Как переносятся значения

Значения из ЗУП приходят через COM в виде COM-объектов. Для каждого значения в базе-источнике вызываются
`XMLТипЗнч` и `XMLСтрока`, а в ERP значение восстанавливается через `ИзXMLТипа` и `XMLЗначение`.
Это единый механизм для ссылок (по идентификатору), перечислений (по имени значения), `ВидДвиженияНакопления`,
`УникальныйИдентификатор` и т.п. Примитивные значения (строки, числа, даты, булево) передаются как есть.
Результаты сопоставления кэшируются, так что каждое значение ищется один раз.

Наборы записей пишутся с `ОбменДанными.Загрузка = Истина`: подписки и проверки при записи не выполняются.
Перед загрузкой в рабочую базу сделайте резервную копию и проверьте результат на копии.
