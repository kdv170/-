# Загрузка данных для НДФЛ из ЗУП в ERP через COM

Внешняя обработка для **1С:ERP Управление предприятием (2.4 / 2.5)**,
загружающая данные регистра учета НДФЛ из **1С:ЗУП 3.1** через COM-соединение.

## Что делает обработка

1. Подключается к базе ЗУП через `V83.COMConnector` (или `V82.COMConnector`)
   в файловом или клиент-серверном варианте работы.
2. Читает записи регистра накопления за период:
   - `УчетДоходовДляИсчисленияНДФЛ` (основной сценарий),
   - `РасчетыНалогоплательщиковСБюджетомПоНДФЛ` (исчислено / удержано),
   - любой другой регистр накопления (универсальный режим — текст запроса строится
     по метаданным базы-корреспондента, поэтому обработка не ломается при
     переименовании измерений в новых релизах ЗУП).
3. Показывает полученные строки в таблице формы, сопоставляет физических лиц
   ЗУП → ERP (по ИНН, затем по ФИО + дате рождения).
4. Создает в ERP документ **`ОперацияУчетаНДФЛ`** и заполняет его табличные части
   по совпадающим именам колонок (работает на разных версиях ERP, где состав
   ТЧ `Доходы` / `Вычеты` / налога может отличаться).

Безопасный режим обработки должен быть **отключен** — иначе COM недоступен.

## Состав исходников

Каталог `zup_ndfl_loader/` — это исходники обработки в «разобранном» виде
(так их хранят для EDT / v8unpack / OneScript):

| Файл | Назначение |
|---|---|
| `ExternalDataProcessor.xml` | Паспорт обработки: имя, синоним, версия, признак безопасного режима |
| `ObjectModule.bsl` | Модуль объекта: `СведенияОВнешнейОбработке()` + серверное создание `ОперацияУчетаНДФЛ` |
| `ManagedFormModule.bsl` | Модуль управляемой формы: COM-подключение, запрос к ЗУП, сопоставление, вызов загрузки |
| `FormDescription.md` | Какие реквизиты и команды создать на форме в Конфигураторе |
| `ПримерСтрокПодключения.txt` | Примеры строк COM-соединения для файловых и серверных баз |

## Быстрый старт (5 минут)

### Вариант А — собрать .epf вручную (без EDT, только Конфигуратор)

1. В ERP: **НСИ и администрирование → Печатные формы, отчеты и обработки →
   Дополнительные отчеты и обработки → Добавить из файла**. Но сначала файл надо создать:
2. Откройте Конфигуратор ERP → **Файл → Новый → Внешняя обработка**.
3. В дереве объектов:
   - скопируйте целиком `ObjectModule.bsl` в **модуль объекта**;
   - создайте форму `ФормаЗагрузки` (управляемая), в ее модуль скопируйте
     целиком `ManagedFormModule.bsl`;
   - реквизиты и команды формы создайте по списку из `FormDescription.md`
     (имена обязаны совпадать — код обращается к ним по именам);
   - в свойствах обработки снимите **Безопасный режим** (или верните `Ложь`
     в `СведенияОВнешнейОбработке` — уже сделано).
4. **Действия → Сохранить как внешний отчет/обработку** → `ЗагрузкаНДФЛизЗУП.epf`.
5. Зарегистрируйте .epf в ERP как дополнительную обработку
   (публикация «Использовать» + нужные разделы/пользователи).
6. Откройте обработку, заполните параметры подключения к ЗУП
   (примеры — в `ПримерСтрокПодключения.txt`), нажмите
   **«Подключиться и получить данные»**, проверьте таблицу, отметьте строки
   флагом, нажмите **«Создать Операцию учета НДФЛ»**.

### Вариант Б — через EDT

1. Создайте проект внешней обработки в EDT, импортируйте файлы каталога
   (`ExternalDataProcessor.xml` как дескриптор, `*.bsl` как модули).
2. Форму соберите по `FormDescription.md` либо импортируйте свою.

## Параметры подключения

- **Вариант ИБ ЗУП**: `Файловая` или `Клиент-серверная`.
- **Файловая**: путь каталога базы, например `C:\Bases\ZUP`.
- **Клиент-серверная**: имя сервера `srv1c:1541` + имя базы `zup_prod`.
- **Пользователь / Пароль** — учетка ЗУП с правами на чтение регистров
  и справочников `ФизическиеЛица`, `Организации`.
- **COM-объект**: `V83.COMConnector` (рекомендуется, платформы 8.3.10+),
  запасной — `V82.COMConnector`.
- **Период**: начало/конец выборки по полю `Период` регистра.
- **Организация**: отбор по организации (сопоставление по наименованию;
  если оставить пустой — выгрузятся все организации).
- **Регистр ЗУП**: имя регистра накопления в ЗУП (по умолчанию
  `УчетДоходовДляИсчисленияНДФЛ`).
- **Создавать ненайденных физлиц**: если `Ложь` (по умолчанию) — несопоставленные
  строки помечаются и не попадают в документ; если `Истина` — создаются новые
  элементы `ФизическиеЛица` с ИНН/ФИО из ЗУП (требует прав на запись справочника).

## Как работает сопоставление

| Сущность | Правило |
|---|---|
| Физлицо | 1) поиск по `ИНН` → 2) по `Наименование` + `ДатаРождения` → 3) по точному `Наименование` → 4) опционально создать нового |
| Организация (шапка документа) | Выбирается вручную в ERP; отбор в ЗУП идет по совпадению наименования |
| Строки регистра → ТЧ документа | Только колонки, имена которых есть и в выгрузке, и в метаданных ТЧ ERP (`КодДохода`, `СуммаДохода`, `СуммаВычета`, `ДатаПолученияДохода`, …). Неизвестные колонки игнорируются — документ проведется |

## Ограничения и безопасность

- COM работает только под Windows и **не работает в веб-клиенте** —
  открывайте обработку в тонком/толстом клиенте.
- Пароль хранится только в реквизите формы и в строке соединения в памяти,
  никуда не записывается. Не давайте полные права на ИБ ЗУП сервисному пользователю.
- Большие периоды выгружайте по месяцам: выборка 100–200 тыс. записей через COM
  занимает минуты; в форме есть счетчик строк и отбор по организации.
- Перед рабочей загрузкой сверьте один месяц с отчетом «Налоговый учет по НДФЛ»
  в ЗУП и с карточкой `ОперацияУчетаНДФЛ` в ERP.
- Имена измерений регистра читаются из метаданных ЗУП через COM, поэтому смена
  релиза ЗУП (например, появление `ГоловнаяОрганизация` вместо `Организация`)
  обрабатывается автоматически, без правки кода.

## Проверка после загрузки

1. Откройте созданный `ОперацияУчетаНДФЛ`, проверьте месяц налогового периода,
   организацию, количество строк `Доходы`.
2. Проведите документ, откройте **ОСВ по регистру `УчетДоходовДляИсчисленияНДФЛ`**
   за месяц — обороты должны совпасть с отчетом ЗУП.
3. Если часть строк не сопоставилась — колонка `Проблема` в таблице формы
   подскажет причину (нет ИНН, дубль ФИО, не найдено физлицо).
