# Перенос исполнительных листов из 1С:ЗУП 3.1 в 1С:ERP

Внешняя обработка `ПереносИсполнительныхЛистов` переносит документы **«Исполнительный лист»**
из базы «Зарплата и управление персоналом 3.1» в базу «ERP Управление предприятием 2».

Документы отбираются **по регистру сведений «ПлановыеУдержания»**: переносятся только те
исполнительные листы, удержания по которым действуют на указанную дату переноса.

## Состав репозитория

```
ПереносИсполнительныхЛистов/
├── ПереносИсполнительныхЛистов.xml                  # описание обработки (реквизиты, табличные части)
└── ПереносИсполнительныхЛистов/
    ├── Ext/ObjectModule.bsl                         # модуль объекта: отбор, выгрузка, загрузка
    └── Forms/
        ├── Форма.xml                                # описание формы (метаданные)
        └── Форма/Ext/
            ├── Form.xml                             # элементы управляемой формы
            └── Form/Module.bsl                      # модуль формы
```

Исходники выгружены в формате конфигуратора («Выгрузить в файлы»), поэтому `.epf` собирается
штатной командой платформы.

## Сборка `.epf`

```bat
"C:\Program Files\1cv8\<версия>\bin\1cv8.exe" DESIGNER /F "<путь к любой базе ЗУП или ERP>" ^
  /LoadExternalDataProcessorOrReportFromFiles "<репозиторий>\ПереносИсполнительныхЛистов\ПереносИсполнительныхЛистов.xml" ^
  "<репозиторий>\ПереносИсполнительныхЛистов.epf"
```

Либо в конфигураторе: *Файл → Открыть* выбрать `ПереносИсполнительныхЛистов.xml` — конфигуратор
предложит сохранить обработку как `.epf`.

Одна и та же обработка используется в обеих базах: в ЗУП — для выгрузки, в ERP — для загрузки.
Обработка не зависит от БСП и других общих модулей конфигураций.

## Порядок переноса

### 1. База ЗУП — страница «Выгрузка из ЗУП»

1. Укажите **дату переноса** (как правило, дата начала расчёта зарплаты в ERP) и при необходимости организацию.
2. Нажмите **«Заполнить список»**. В список попадут исполнительные листы, для которых одновременно:
   - в срезе последних регистра сведений `ПлановыеУдержания` на конец дня даты переноса есть
     действующая запись (`Действует = Истина`) с документом-основанием `Документ.ИсполнительныйЛист`;
   - документ проведён и не помечен на удаление;
   - `ДатаНачала <= ДатаПереноса` и (`ДатаОкончания` не заполнена или `ДатаОкончания >= ДатаПереноса`).
3. Снимите отметки с документов, которые переносить не нужно, и нажмите **«Выгрузить в файл»**.
   Будет сформирован файл `ИсполнительныеЛисты_<дата>.xml`.

### 2. База ERP — страница «Загрузка в ERP»

1. Задайте настройки:

   | Настройка | Назначение |
   |---|---|
   | Проводить документы | Записывать документы с проведением (формируются движения по `ПлановыеУдержания` в ERP). Непроведённые в ЗУП документы в любом случае записываются без проведения. |
   | Обновлять существующие документы | Если документ с таким же идентификатором уже есть в ERP — перезаполнить его. По умолчанию такие документы пропускаются. |
   | Переносить номера документов | Сохранять номера из ЗУП. Отключите, если в ERP возможен конфликт нумерации. |
   | Сохранять даты документов | Сохранять дату документа из ЗУП. Если отключено — новые документы получают дату переноса (полезно при закрытом периоде). |
   | Создавать отсутствующих получателей | Если получатель (контрагент) не найден в ERP — создать его (вместе с партнёром) по ИНН/КПП и наименованию из файла. |

2. Нажмите **«Загрузить из файла»** и выберите файл, выгруженный из ЗУП.
3. В таблице «Результат загрузки» по каждому документу отображается статус (`Создан`, `Обновлен`,
   `Пропущен`, `Ошибка`) и сообщения: какие реквизиты не удалось сопоставить, какие получатели созданы и т. п.

## Как сопоставляются данные

Документы в ERP создаются **с тем же уникальным идентификатором**, что и в ЗУП. Поэтому повторная
загрузка файла не создаёт дублей, а при включённом флаге «Обновлять существующие» перезаполняет документы.

Состав переносимых реквизитов и табличных частей определяется по метаданным: переносятся реквизиты,
имеющиеся и в ЗУП, и в ERP. Реквизит `Ответственный` не переносится и заполняется текущим пользователем ERP.

Ссылочные реквизиты ищутся в ERP в следующем порядке: предопределённый элемент (по имени) → тот же
уникальный идентификатор → ключевые поля:

| Объект | Порядок поиска по ключевым полям |
|---|---|
| Организации, Контрагенты | ИНН + КПП → ИНН → Наименование → Полное наименование |
| Физические лица | СНИЛС → ИНН → Фамилия + Имя + Отчество + Дата рождения → Наименование + Дата рождения → Наименование |
| Сотрудники | Физлицо + Головная организация + Код → Физлицо + Головная организация → Физлицо + Код → Физлицо → Код → Наименование |
| Виды удержаний и прочие | Предопределённое имя → Код → Наименование |
| Перечисления | По имени значения перечисления |

Пустые ключевые значения (например, незаполненный ИНН) при поиске не используются. Элементы,
помеченные на удаление, и группы справочников имеют меньший приоритет / исключаются.

Если не удалось сопоставить **Организацию, Сотрудника или Получателя**, документ не создаётся
(статус «Ошибка» с указанием причины). Остальные несопоставленные реквизиты остаются незаполненными,
о чём выводится предупреждение.

## Предварительные условия в ERP

- Включён кадровый учёт и расчёт зарплаты в ERP (документ `ИсполнительныйЛист` доступен).
- Перенесены организации, физические лица и сотрудники (кадровые данные), иначе документы
  не будут сопоставлены.
- Получатели (контрагенты) либо перенесены заранее, либо включён флаг
  «Создавать отсутствующих получателей». Созданных получателей рекомендуется проверить.

## Ограничения и примечания

- Обмен выполняется через файл, прямое COM-соединение не используется — обработка работает
  на любой платформе (включая серверы Linux) и в веб-клиенте.
- Текст запроса отбора строится по метаданным регистра `ПлановыеУдержания` (имя поля
  документа-основания, наличие ресурса `Действует`, периодичность), поэтому обработка устойчива
  к различиям между релизами ЗУП 3.1.
- Исходники написаны без доступа к рабочим базам ЗУП/ERP; перед промышленным использованием
  выполните проверку на копиях баз.
