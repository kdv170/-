# Перенос исполнительных листов из 1С:ЗУП в 1С:ERP

Внешняя обработка переносит документы `ИсполнительныйЛист` из ЗУП 3.1 в ERP 2.5
через промежуточный JSON-файл.

Документы выгружаются не по периоду их создания, а по регистру сведений
`ПлановыеУдержания`: обработка получает `СрезПоследних` на конец даты переноса,
оставляет записи с `Используется = Истина` и основания типа
`Документ.ИсполнительныйЛист`.

Если условия листа менялись, в пакет накладываются реквизиты актуального
регистратора `ИзменениеУсловийИсполнительногоЛиста`. Для удержаний с пределом
в ERP передается остаток на дату переноса из регистра накопления
`УдержанияДоПределаПоСотрудникам`, а не первоначальная сумма долга.

## Сборка

Исходники находятся в `src` и имеют штатный формат выгрузки конфигуратора 1С
версии 2.17.

```bash
DESIGNER=/opt/1cv8/x86_64/8.3.xx.xxxx/1cv8 \
IB_CONNECTION='/F/path/to/empty-infobase' \
./scripts/build.sh
```

Готовый файл будет записан в `build/ПереносИсполнительныхЛистов.epf`.
Для сборки нужна установленная платформа 1С и доступная служебная
информационная база. Ее конфигурация может быть пустой.

Альтернативно создайте в конфигураторе пустую внешнюю обработку и выполните
для нее «Действия → Загрузить из файлов», указав
`src/ПереносИсполнительныхЛистов.xml`, затем сохраните обработку как EPF.

## Использование

1. Запустите толстый клиент ЗУП в режиме управляемого приложения.
2. Откройте EPF через «Файл → Открыть», задайте дату переноса и нажмите
   «Выгрузить в ЗУП».
3. Сделайте резервную копию ERP.
4. Откройте тот же EPF в ERP, при необходимости отключите проведение и нажмите
   «Загрузить в ERP».
5. Проверьте протокол и созданные документы.

Обработка переносит совпадающие реквизиты и табличные части. Ссылки
сопоставляются только с уже существующими объектами ERP:

- организации и контрагенты — по ИНН/КПП;
- физические лица — по СНИЛС, затем ИНН, затем ФИО и дате рождения;
- сотрудники — по физическому лицу, организации и табельному номеру;
- банковские счета контрагентов — по номеру счета;
- прочие справочники и планы видов расчета — по наименованию;
- перечисления — по внутреннему имени значения.

Новые элементы справочников автоматически не создаются. Отсутствующая или
неоднозначно найденная ссылка приводит к ошибке конкретного документа и
отражается в протоколе. Остальные документы продолжают загружаться.

Повторная загрузка безопасна: в комментарий документа записывается UUID
исходного документа, по которому обработка исключает дубли. Повторная проверка
выполняется под исключительной блокировкой документов `ИсполнительныйЛист`,
поэтому параллельные загрузки одного пакета не создают копии.

## Совместимость

Решение рассчитано на типовые ЗУП 3.1 и ERP 2.5 на платформе 8.3.18 или новее.
При измененном составе регистра или документа обработка завершится понятной
ошибкой либо пропустит отсутствующий необязательный реквизит. Перед рабочим
переносом рекомендуется проверить результат на копиях обеих баз.
