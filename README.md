# Обработка переноса документов «Исполнительный лист» из 1С:ЗУП 3.1 в 1С:ERP 2

Универсальная внешняя обработка для переноса документов **«Исполнительный лист»** (`Документ.ИсполнительныйЛист`) из конфигурации **1С:Зарплата и управление персоналом 3.1** в **1С:ERP Управление предприятием 2** (а также **1С:Комплексная автоматизация 2**).

---

## 📋 Основные возможности

- **Отбор по регистру сведений `ПлановыеУдержания`**: в перенос попадают только те исполнительные листы, удержания по которым **действуют на указанную дату переноса**.
- **Поддержка двух форматов обмена**: структурированный **XML** и легковесный **JSON**.
- **Два сценария переноса**:
  1. *Двухэтапный через файл*: выгрузка из базы-источника ЗУП 3.1 в файл и загрузка в базу-приемник ERP 2.
  2. *Прямой перенос через COM-соединение (`V83.COMConnector`)*: перенос «на лету» без промежуточных файлов между файловыми или клиент-серверными базами.
- **Интеллектуальное сопоставление нормативно-справочной информации (НСИ)**:
  - Организации (по ИНН/КПП, наименованию);
  - Физические лица (по СНИЛС, ИНН, ФИО и дате рождения);
  - Сотрудники (по физ. лицу + организации, табельному номеру);
  - Получатели / Контрагенты (по ИНН/КПП, наименованию);
  - Банковские счета контрагентов (по номеру счета, БИК банка);
  - Виды расчетов / удержаний (по предопределенным элементам, коду, наименованию, категории удержания);
  - Перечисления (виды исполнительных документов, способы расчета, очередность взыскания).
- **Контроль дублей документов**: поиск существующих документов по UUID и связке «Организация + Сотрудник + Номер исполнительного документа».
- **Режимы записи в ERP**: проведение или запись без проведения, перезапись существующих или пропуск.
- **Совместимость с БСП**: модуль объекта содержит стандартную функцию `СведенияОВнешнейОбработке()`, что позволяет регистрировать обработку в справочнике *«Дополнительные отчеты и обработки»*.
- **Подробный журнал операций**: отображение протокола сопоставления, созданных, обновленных и пропущенных объектов.

## 🔍 Логика отбора по регистру сведений «ПлановыеУдержания»

В конфигурациях ЗУП 3.1 и ERP 2 назначение и прекращение удержаний по исполнительным листам фиксируется в регистре сведений `ПлановыеУдержания` (периодический с подчинением регистратору).

В обработке отбор действующих исполнительных листов реализован через виртуальную таблицу **`СрезПоследних(&КонецДняПереноса)`**:

```bsl
ВЫБРАТЬ РАЗЛИЧНЫЕ
    ПлановыеУдержанияСрез.ДокументОснование КАК ДокументОснование,
    ПлановыеУдержанияСрез.Сотрудник КАК Сотрудник,
    ПлановыеУдержанияСрез.Удержание КАК Удержание,
    ПлановыеУдержанияСрез.Размер КАК РазмерИзРегистра,
    ПлановыеУдержанияСрез.Действует КАК ДействуетПоРегистру,
    ПлановыеУдержанияСрез.ДействуетДо КАК ДействуетДоПоРегистру
ПОМЕСТИТЬ ВТ_ДействующиеПлановыеУдержания
ИЗ
    РегистрСведений.ПлановыеУдержания.СрезПоследних(
        &КонецДняПереноса,
        ДокументОснование ССЫЛКА Документ.ИсполнительныйЛист
            И (&ОтборОрганизация = НЕОПРЕДЕЛЕНО
                ИЛИ &ОтборОрганизация = ЗНАЧЕНИЕ(Справочник.Организации.ПустаяСсылка)
                ИЛИ ДокументОснование.Организация = &ОтборОрганизация)
            И (&ОтборСотрудник = НЕОПРЕДЕЛЕНО
                ИЛИ &ОтборСотрудник = ЗНАЧЕНИЕ(Справочник.Сотрудники.ПустаяСсылка)
                ИЛИ Сотрудник = &ОтборСотрудник)) КАК ПлановыеУдержанияСрез
ГДЕ
    ПлановыеУдержанияСрез.Действует = ИСТИНА
    И (ПлановыеУдержанияСрез.ДействуетДо = ДАТАВРЕМЯ(1, 1, 1)
        ИЛИ ПлановыеУдержанияСрез.ДействуетДо >= &НачалоДняПереноса)
```

### Ключевые аспекты отбора:
1. **Ресурс `Действует = ИСТИНА`**: отсекает удержания, которые были прекращены документами *«Изменение исполнительного листа»* или завершились по достижению предела.
2. **Реквизит `ДействуетДо`**: если дата окончания зафиксирована в регистре, проверяется условие `ДействуетДо >= ДатаПереноса`.
3. **Статус документа-основания**: отбираются только проведенные документы (`Док.Проведен = ИСТИНА`) без пометки удаления.
4. **Опция строгого соответствия периоду**: флаг *«Проверять период действия документа»* дополнительно сверяет `ДатаНачала <= ДатаПереноса` и `(ДатаОкончания пустая ИЛИ ДатаОкончания >= ДатаПереноса)`.
5. **Резервный алгоритм**: при нестандартных доработках конфигурации предусмотрен резервный запрос, гарантирующий выборку данных.

## 🧩 Правила сопоставления объектов (НСИ)

| Тип объекта в ERP | Приоритет сопоставления | Создание нового (если включено) |
|---|---|---|
| **Организация** | 1. ИНН + КПП<br>2. Точное совпадение наименования | Создается с ИНН, КПП, ОГРН и наименованием |
| **Физическое лицо** | 1. СНИЛС (`СтраховойНомерПФР`)<br>2. ИНН<br>3. ФИО + Дата рождения | Создается с ФИО, СНИЛС, ИНН, датой рождения, полом |
| **Сотрудник** | 1. Физ. лицо + Головная организация<br>2. Табельный номер (Код) + Организация | Создается с привязкой к физ. лицу и организации |
| **Получатель (Контрагент)** | 1. ИНН + КПП<br>2. Точное наименование | Создается с ИНН, КПП, наименованием, признаком Юр/ФизЛицо |
| **Банковский счет** | 1. Номер счета + Владелец (Контрагент) | Создается с привязкой к банку по БИК из классификатора |
| **Вид удержания** | 1. Предопределенное удержание (`ИсполнительныйЛист`, `...Процентом`, `...ФиксированнойСуммой`, `...Долей`)<br>2. Код удержания<br>3. Наименование<br>4. Категория удержания `ИсполнительныйЛист` | Используется найденный вид расчета |
| **Перечисления** | По символьному идентификатору имени значения перечисления | Безопасная обработка с подстановкой значения по умолчанию |

## 🚀 Инструкция по использованию

### Вариант 1. Запуск через «Файл» -> «Открыть»
1. Откройте **1С:ЗУП 3.1** или **1С:ERP 2**.
2. Перейдите в меню `Главное меню` -> `Файл` -> `Открыть...` (или комбинация `Ctrl + O`).
3. Выберите файл `ПереносИсполнительныхЛистовИзЗУПвERP.epf`.

### Вариант 2. Регистрация в справочнике «Дополнительные отчеты и обработки» (БСП)
1. В меню ERP или ЗУП перейдите: `НСИ и администрирование` -> `Печатные формы, отчеты и обработки` -> `Дополнительные отчеты и обработки`.
2. Нажмите кнопку **«Добавить из файла...»** и выберите `ПереносИсполнительныхЛистовИзЗУПвERP.epf`.
3. Укажите разделы командного интерфейса (например, *«Зарплата»* или *«Кадры»*) и сохраните.

## 🖥️ Пошаговые сценарии работы

### Сценарий А: Перенос через файл обмена (рекомендуемый)
1. **В базе 1С:ЗУП 3.1**:
   - Откройте обработку.
   - Выберите режим **«0 — Выгрузка из ЗУП»**.
   - Укажите **Дату переноса** (на которую проверяется действие удержаний).
   - При необходимости укажите отбор по конкретной Организации или Сотруднику.
   - Нажмите **«Заполнить по регистру»** — таблица заполнится действующими исполнительными листами.
   - Отметьте нужные строки (кнопки *«Отметить все»* / *«Снять отметки»*).
   - Выберите формат файла (**XML** или **JSON**) и укажите путь сохранения.
   - Нажмите **«Выгрузить в файл»**.
2. **В базе 1С:ERP 2**:
   - Откройте обработку.
   - Выберите режим **«1 — Загрузка в ERP»**.
   - Выберите ранее выгруженный файл (XML или JSON).
   - Настройте параметры загрузки:
     - *Проводить загруженные документы* (по умолчанию включено);
     - *Перезаписывать существующие документы* (если требуется обновить уже имеющиеся);
     - *Создавать новые элементы справочников* (создаст контрагентов, физлиц, счета, если их еще нет в ERP);
     - *Устанавливать исходный номер и дату*.
   - Нажмите **«Загрузить в ERP»**.
   - Результаты и статистика отобразятся в **Журнале сообщений**.

### Сценарий Б: Прямой перенос через COM-соединение
1. Откройте обработку в целевой базе **1С:ERP 2**.
2. Выберите режим **«2 — Прямой перенос COM»**.
3. Укажите параметры подключения к базе 1С:ЗУП:
   - Тип подключения: *Файловый* (каталог базы) или *Серверный* (кластер 1С + имя базы);
   - Пользователь и пароль администратора базы ЗУП.
4. Нажмите кнопку **«Проверить COM-подключение»** — обработка проверит связь и покажет имя/версию базы ЗУП.
5. Задайте дату переноса и параметры загрузки.
6. Нажмите **«Выполнить прямой перенос»** — документы будут прочитаны напрямую из ЗУП и созданы/проведены в ERP.
