# Перенос исполнительных листов из ЗУП в ERP

Внешняя обработка `ПереносИсполнительныхЛистовЗУП` переносит документы `ИсполнительныйЛист` из 1С:ЗУП 3.1 в 1С:ERP. В файл попадают только листы, которые действуют на выбранную дату.

Одна и та же обработка открывается в обеих базах: в ЗУП она выгружает файл, в ERP загружает документы.

## Кого обрабатываем

Документ попадает в список, если одновременно выполняется следующее:

- документ проведён и не помечен на удаление;
- на конец даты переноса срез регистра сведений `ПлановыеУдержания` содержит запись, у которой `ДокументОснование` — этот исполнительный лист;
- ресурс `Используется` включён;
- `ДействуетДо` пустая или не раньше даты переноса;
- заполненная дата окончания документа не раньше даты переноса.

Дата переноса включает весь день: срез строится на 23:59:59. Несколько записей регистра по одному листу (например, по разным сотрудникам) дают одну строку. Закрытые и ещё не начавшиеся удержания в файл не входят.

Регистр в ERP заново заполняет проведение документа. Записи регистра из ЗУП копируются в файл только как основание отбора.

## Как собрать EPF

Исходники лежат в каталоге `src` в формате выгрузки конфигуратора. Собирать обработку нужно в базе ЗУП или ERP: на форме есть ссылка `Справочник.Организации`.

```text
1cv8.exe DESIGNER /F "C:\Bases\ZUP" /DisableStartupDialogs /LoadExternalDataProcessorOrReportFromFiles "C:\src\src" "C:\src\ПереносИсполнительныхЛистовЗУП.epf"
```

Первый путь — каталог, в котором лежит `ПереносИсполнительныхЛистовЗУП.xml`. Второй — файл обработки, который нужно получить.

## Как переносить

1. Откройте EPF в ЗУП. Укажите дату переноса и, если нужно, организацию.
2. Нажмите «Заполнить по регистру», снимите флажки с листов, которые переносить не нужно, и выгрузите файл JSON.
3. Откройте тот же EPF в ERP. Прочитайте файл и нажмите «Загрузить в базу».
4. По журналу проверьте проведённые документы и строки с ошибками.

Повторная загрузка находит уже созданный документ по уникальному идентификатору ЗУП, затем по маркеру `ПереносЗУП:<УИД>` в комментарии, затем по номеру и дате, затем по физическому лицу, удержанию и дате начала. Номер и дата документа сохраняются.

## Как сопоставляются справочники

| Данные | Правило |
| --- | --- |
| Организации | ИНН и КПП, затем ИНН, если организация одна. Новые не создаются. |
| Удержания | Предопределённое имя, код, затем точное наименование. Новые не создаются. |
| Физические лица | СНИЛС, затем ИНН, затем фамилия, имя и дата рождения. Можно создать. |
| Сотрудники | Табельный номер, физическое лицо и головная организация. Создание выключено: карточка появится без приёма на работу. |
| Контрагенты | ИНН и КПП, затем ИНН. Можно создать. |
| Банки и счета | БИК и номер счёта владельца. Можно создать. |

Если организация, физическое лицо, удержание, получатель или счёт из ЗУП не найдены, документ не записывается, причина попадает в журнал. Сотрудник, ответственный и бухгалтер при отсутствии в ERP документ не блокируют.

Проведение включено по умолчанию. Если новый документ не проводится, обработка записывает его непроведённым. Уже проведённый документ перепроводится, чтобы движения совпали с новыми данными; если перепроведение не удалось, прежняя проведённая версия остаётся без изменений.
