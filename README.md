# Перенос исполнительных листов из ЗУП в ERP

Внешняя обработка `ПереносИсполнительныхЛистовЗУП` открывается в базе ERP и читает документы `ИсполнительныйЛист` из базы ЗУП по COM-соединению. В список попадают листы, которые действуют на выбранную дату. Загрузка создаёт и проводит документы в текущей базе.

Файл JSON остаётся запасным путём: тот же список можно выгрузить и прочитать в другой базе ERP.

## Кого обрабатываем

Документ попадает в список, если одновременно выполняется следующее:

- документ проведён и не помечен на удаление;
- на конец даты переноса срез регистра сведений `ПлановыеУдержания` содержит запись, у которой `ДокументОснование` — этот исполнительный лист;
- ресурс `Используется` включён;
- `ДействуетДо` пустая или не раньше даты переноса;
- заполненная дата окончания документа не раньше даты переноса.

Дата переноса включает весь день: срез строится на 23:59:59. Несколько записей регистра по одному листу дают одну строку. Закрытые и ещё не начавшиеся удержания в список не входят.

Регистр в ERP заново заполняет проведение документа. Записи регистра из ЗУП попадают в пакет только как основание отбора.

## Как собрать EPF

Исходники лежат в каталоге `src` в формате выгрузки конфигуратора. Собирать обработку нужно в базе ERP или ЗУП: на форме есть ссылка `Справочник.Организации`.

```text
1cv8.exe DESIGNER /F "C:\Bases\ERP" /DisableStartupDialogs /LoadExternalDataProcessorOrReportFromFiles "C:\src\src" "C:\src\ПереносИсполнительныхЛистовЗУП.epf"
```

Первый путь — каталог, в котором лежит `ПереносИсполнительныхЛистовЗУП.xml`. Второй — файл обработки, который нужно получить.

## Как переносить

Обработка запускается в ERP. Список читает тонкий или толстый клиент Windows: COM-соединение создаётся на компьютере пользователя, сервер ERP к базе ЗУП не обращается. Веб-клиент такое соединение открыть не может. Разрядность клиента и `V83.COMConnector` должна совпадать. Если платформа блокирует опасные действия, их нужно разрешить для этой обработки.

1. Откройте EPF в ERP.
2. Укажите базу ЗУП. Для файловой базы включите «Файловая база» и выберите каталог. Для клиент-серверной укажите сервер и имя базы, как в параметрах `Srvr` и `Ref` строки соединения.
3. Укажите пользователя и пароль ЗУП. Пароль нужен только для соединения и в журнал не записывается.
4. Укажите дату переноса и, если нужно, организацию ERP. Организация ищется в ЗУП по ИНН и КПП.
5. Нажмите «Заполнить из ЗУП», снимите флажки с листов, которые переносить не нужно, и нажмите «Загрузить в базу».
6. По журналу проверьте проведённые документы и строки с ошибками.

Повторная загрузка находит уже созданный документ по уникальному идентификатору ЗУП, затем по маркеру `ПереносЗУП:<УИД>` в комментарии, затем по номеру и дате, затем по физическому лицу, удержанию и дате начала. Номер и дата документа сохраняются.

## Как сопоставляются справочники

| Данные | Правило |
| --- | --- |
| Организации | ИНН и КПП, затем ИНН, если организация одна. Новые не создаются. |
| Удержания | Предопределённое имя, код, затем точное наименование. Новые не создаются. |
| Физические лица | СНИЛС, затем ИНН, затем фамилия, имя и дата рождения. Можно создать. |
| Сотрудники | Табельный номер, физическое лицо и головная организация. Создание выключено: карточка появится без приёма на работу. |
| Контрагенты | ИНН и КПП, затем ИНН. Можно создать. |
| Банки и счета | БИК и номер счёта владельца. Можно создать. |

Если организация, физическое лицо, удержание, получатель или счёт из ЗУП не найдены, документ не записывается, причина попадает в журнал. Сотрудник не блокирует документ, когда физическое лицо заполнено. Ответственный и бухгалтер при отсутствии в ERP документ не блокируют.

Проведение включено по умолчанию. Если новый документ не проводится, обработка записывает его непроведённым. Уже проведённый документ перепроводится, чтобы движения совпали с новыми данными; если перепроведение не удалось, прежняя проведённая версия остаётся без изменений.
